Today the app counts issues straight from each repo and cannot add tasks, and `npm run tasks:sync` (run by hand) turns a `TASKS.md` into issues one way. The owner's decision: **the GitHub Project is the source of truth**, because the web app will be able to add tasks and milestones. `TASKS.md` stops being the master and becomes a generated copy that Claude sessions can read cold. See `PLANNING.md` ("GitHub Project as the source of truth") for the design and the conflict rules, and `docs/onboarding-repos.md` for the rules every onboarded repo follows.
